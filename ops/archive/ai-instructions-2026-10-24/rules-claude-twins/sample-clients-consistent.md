# Sample clients make sense

**Owner law (2026-10-02):** Every sample client is one realistic person. Buyers are educated. A sample that contradicts itself tells them the product is fake.

## Law

A sample client is anyone shown as an example: "See a sample" previews, sample documents, demos, ads, VSL screens, sales decks.

- One person, one credit file, one story. Every document in the set comes from that same file.
- The numbers agree with each other. What they qualify for today, what they qualify for after, the amount left on the table, the negative items, the letters, and the roadmap steps must all follow from that one file.
- Negative items show up only if the file has them. A clean file gets no dispute letter. A file with charge-offs does not qualify for a big number today.
- Run the file through UnderwriteIQ (the IQ rules). Print what the engine prints. Do not hand-edit a number to make it look better.
- If no single file can tell the whole story, say so and stop. Do not stitch two files together.

## Never

- A $199,000 approval today next to a dispute letter for a charge-off
- Numbers from one file and letters from another
- A dollar amount, score, account, or step the engine did not print for that file
- A real client's file on a public page

## Always

- Pick or build one sample file that fits the story first, then run every document from it
- Check every number in the set against the others before Chris sees it

## Example

```text
Ask: "Show the six samples on /roadmap."

❌ Qualification from a clean 762 file, dispute letter from a different test file with a charge-off.
✅ One sample file with a few real problems, run end to end through UnderwriteIQ: a modest amount today, a higher amount after the fixes, and letters for the same items the report lists.
```
