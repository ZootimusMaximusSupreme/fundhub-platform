STORED EFFECT AND RETRY RULE
crs_property_requests saves requester, operation, separate immutable permission, normalized report, strict UUID provider receipt, status and timestamps. No raw provider Input, SSN, DOB, token or credential fields are retained. Default app grants are revoked before SELECT/INSERT and narrow status/version/receipt UPDATE grants. A scope trigger binds client and staff to the same company; attribution remains immutable.
identity_fingerprint is an immutable domain-separated HMAC-SHA256 over full normalized name/SSN/DOB and company/client, keyed with existing PII_ENC_KEY. This is the billable dedupe key.
identity_version_fingerprint is the last revalidated encrypted saved version, used for read staleness without decrypting on GET. Re-encrypting the same SSN can make the old view stale, but the next explicit authorized action audits decryption, finds the stable HMAC, rebinds only the version, and returns the original receipt without another provider call. Historical version drift does not itself invalidate historical evidence.
The claim commits before the property wire. In-flight, timeout, rejected or malformed provider responses never automatically retry. Identity changes during the wire hide the earlier report and require review.

CONTROLLED FINDINGS REPAIRED BEFORE HANDOFF
1. Randomized ciphertext was an unsafe billable identity key. Stable keyed full-identity dedupe and a distinct read version now prevent repeat orders on identical SSN re-encryption.
2. Non-success RequestID headers could contain arbitrary text. Every path now uses strict UUID-or-null; canonical lowercase keeps normalized receipt IDs equal to PostgreSQL UUID values.
3. A valid-looking report could coexist with a malformed string error field. All known top-level error fields now reject malformed or nonempty shapes, regardless of string/object/array type.
4. PostgreSQL inherited default table grants could exceed intended privileges.569 explicitly revokes app grants before adding the narrow grants. The final exact migration was applied to the empty guarded scratch table and its restrictions passed the app-role test.
