### Focused native changes owned by this PR

1. **iPhone:** keep first-party `target=_blank` URLs in the authenticated `WKWebView`; exact web login destinations still sign out, external links still open outside, payment-provider subframes aren't intercepted. Added `FundhubTests.swift` unit assertions for same-origin and lookalike domains. These source tests require macOS/Xcode to execute.
2. **Mac:** block unsafe external URL schemes in both navigation callbacks. No changes to web portal, shared staff shell, backend, payments, or live session records. Must run manual native UI checks before declaring live.
3. **Native APNs opt-out hardening:** explicit per-app opt-in state persists independently of iOS authorization and server registration. Refresh refuses to re-register when the user disabled notifications; stale server registrations are revoked and late registration callbacks compensate with deletion. Source/XCTest regression checks added. The native notification card is STILL NOT mounted, no device APNs delivery verified, and no native release was shipped.
4. Explicitly **deferred** native APNs opt-in presentation, Mac Home/account switching logout, and full native status UI: these need separate owner-approved product behavior and/or real device test. They are not silently considered done.

## Future per-client app-first-open / sign-in indicator — **DESIGN ONLY; NOT IMPLEMENTED**

**Semantics.** Do **not** call a marketing CTA click or an App Store download an install/first-open. Without an authenticated user, native app launch has no reliable `client_id`. Define the first defensible checkmark as **“First authenticated iPhone app open”**, meaning the Fundhub native client app successfully verifies a client session and acknowledges a server-recorded event. “Signed in on iPhone” may be the same event if instrumented only after verification; if distinct labels are requested, a separate `native_login_completed` event must be emitted upon fresh login, while `native_authenticated_open` also fires after Keychain restoration. **Do not** use APNs device registration: notifications can be denied, disabled or unavailable.

**Proposed write route** (not present today): `POST /api/native/client-activity` with existing authenticated bearer, client-only principal gate; accept only `event_type` in `native_authenticated_open`, `native_login_completed`; `platform: ios` initially; `installation_id` = random UUID created within native installation; `event_id` = unique UUID generated for retry idempotency; `app_version`, `app_build`; optionally `observed_at` but **server receive time** is authoritative. **Never accept client_id/org_id/account_id from request body or URL:** derive `org_id`, `client_id`, `account_id` from currently live verified session. Ignore staff, partner, affiliate principals. Log no bearer, email, IP, APNs token, Apple ID, IDFA/IDFV, fingerprint or other advertising identifier in tracking payload. Validate each field, cap size, rate-limit and enforce org/client scope on all reads.

**Storage / idempotency.** Proposed private table `native_client_installations` with `org_id, client_id, account_id, platform, installation_id, first_authenticated_at (server), last_authenticated_at (server), last_login_at (server, nullable), app_version, app_build, last_event_id, created_at, updated_at`. Unique `(org_id, client_id, platform, installation_id)`; a separate bounded event ledger keyed by `(org_id, client_id, event_id)` for duplicate retries if event-level timing matters. An atomic transaction inserts-or-updates by the trusted server principal and preserves the earliest server timestamp; replay never creates duplicate installations or moves the first timestamp. Retain a first-event proof/source, even after successive logins. A reinstall may change the UUID; a Keychain-backed ID could survive reinstall, so never present install count as unique hardware count. A token alone doesn't prove the request came from an untampered native app; app-attestation may later be considered if a high-assurance attestation is required.

**Client dashboard indicator.** Render checkbox **only** from the authorized server read of the matching client installation row, with provenance label `Native client authenticated`, platform, first timestamp, last timestamp and app build; show `Not observed` when absent, **not** `Not installed`. Keep separate optional marketing `download_link_clicked_at` (attributed by authenticated click/first-party session when available), separate platform/source, never conflate it with native open. Staff read must enforce current org/client authorization; client portal should not expose other clients' events.

**Privacy and approval.** Disclose native usage-data collection in privacy notice / App Store privacy metadata as applicable, minimize installation ID scope, disable third-party advertising reuse, define a reasonable retention period (proposed 90-day raw retries; client service-activity summary retained only as needed under retention policy), support deletion requests, and review consent/legal requirements before rollout. The owner specifically deferred backend/dashboard event implementation; **do not ship it from this PR**.
